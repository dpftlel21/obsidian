# 면접자현황 결재선 매핑 지옥

## 문제 개요
- **발생 기간**: 2026년 3월 - 4월 (약 3-4주)
- **심각도**: ⭐⭐⭐⭐⭐ (최고)
- **영향도**: 결재 시스템 전체 마비

## 문제 현상

### 초기 문제 발견
```javascript
// 초기 문제: 직급별 결재선 매핑이 일관성이 없음
const approvers = item.approvers?.map(approver => {
  // 문제 1: 지원본부 vs 일반본부 처리 로직 부재
  // 문제 2: 직급(positionNm)과 직책(dutyNm) 구분 애매
  // 문제 3: LVL 매핑과 일반 매핑이 섞여있음
  // 문제 4: 특정 사원번호 예외 케이스 다수
})
```

### 구체적 혼란 상황
1. **동일 직급 다른 매핑**: "본부장"이 어떤 곳에서는 "본부장", 어떤 곳에서는 "실장"
2. **지원본부 특수성**: 지원본부의 본부장은 "실장"으로 표시해야 함
3. **LVL과 직책 혼재**: `LVL4`와 `본부장`이 같은 의미인데 다르게 처리
4. **employeeId 기반 예외**: 특정 사원번호는 무조건 특정 직책

### 문제의 복잡성
- **총 26개 케이스**: 각각 다른 매핑 규칙 필요
- **3가지 조건 변수**: 부서(지원본부/일반), 직급코드, 사원번호
- **5가지 출력 형태**: 담당/과장/소장/실장/본부장/지사장/사장/회장/부사장

## 해결 과정

### 1단계: 지원본부 특별 처리 로직 구축 (3월 중순)

```javascript
// 지원본부 판별 로직
const isSupportHeadquarters = 
  item.headquarters?.replace(/\s+/g, '') === '지원본부'

// LVL → 직급 매핑 테이블
const mapLevelToInterviewRank = (level?: string | null): string | null => {
  if (!level) return null
  
  const levelNo = level.replace(/^LVL/i, '')
  const levelMap: Record<string, string> = {
    '1': '담당',
    '2': '소장', 
    '3': '지사장',
    '4': '본부장',  // 일반본부
    '6': '사장',
    '7': '회장',
    '8': '실장',    // 지원본부 전용
    '9': '부사장'
  }
  
  return levelMap[levelNo] || null
}
```

**1단계 성과:**
- LVL 기반 매핑 표준화
- 지원본부 구분 로직 확립
- 기본적인 매핑 규칙 정리

### 2단계: 특정 사원번호 예외 처리 (3월 말)

```javascript
// Hard-coded 예외 처리 (불가피한 비즈니스 요구사항)

```

**2단계 성과:**
- 예외 케이스 명시적 처리
- 비즈니스 요구사항 충족
- 코드 가독성 향상

### 3단계: 직책별 세분화 매핑 (4월 초)

```javascript
// 본부장 처리 (지원본부 vs 일반본부)
if (processed.dutyCd === '105' || duty === '본부장') {
  const rankName = isSupportHeadquarters ? '실장' : '본부장'
  processed.dutyNm = rankName
  processed.positionNm = rankName
  processed.positionCode = rankName
}

// 영업소장 → 소장 매핑
else if (duty === '영업소장') {
  processed.dutyNm = '소장'
  // positionNm은 그대로 유지 (원본 데이터 보존)
}

// 지사장 특별 처리
else if (processed.dutyCd === '103' || duty === '지사장') {
  // 지원본부에는 지사장이 없으므로 실장으로 매핑
  const rankName = isSupportHeadquarters ? '실장' : '지사장'
  processed.dutyNm = rankName
  processed.positionNm = rankName
}

// 기타 직책들
else if (['과장', '차장', '팀장'].includes(duty)) {
  processed.dutyNm = '과장'  // 모두 과장급으로 통합
}
```

**3단계 성과:**
- 모든 직책별 세분화 완료
- 지원본부 특수성 완벽 반영
- 예외 없는 매핑 규칙 확립

### 4단계: 최종 통합 및 검증 (4월 중순)

```javascript
const processApproverForInterview = (approver: any, headquarters?: string) => {
  let processed = { ...approver }
  
  // 1. 지원본부 판별
  const isSupportHeadquarters = 
    headquarters?.replace(/\s+/g, '') === '지원본부'
  
  // 2. 특정 사원번호 예외 처리 (최우선)
  if (SPECIAL_EMPLOYEE_MAPPING[processed.employeeId]) {
    const specialRole = SPECIAL_EMPLOYEE_MAPPING[processed.employeeId]
    processed.dutyNm = specialRole
    processed.positionNm = specialRole
    processed.positionCode = specialRole
    return processed
  }
  
  // 3. LVL 기반 매핑
  if (processed.level) {
    const mappedRank = mapLevelToInterviewRank(processed.level)
    if (mappedRank) {
      // 지원본부 특별 처리
      if (mappedRank === '본부장' && isSupportHeadquarters) {
        processed.dutyNm = '실장'
        processed.positionNm = '실장'
      } else {
        processed.dutyNm = mappedRank
        processed.positionNm = mappedRank
      }
    }
  }
  
  // 4. 직책 기반 매핑 (LVL이 없는 경우)
  else if (processed.dutyNm) {
    const duty = processed.dutyNm
    
    if (processed.dutyCd === '105' || duty === '본부장') {
      const rankName = isSupportHeadquarters ? '실장' : '본부장'
      processed.dutyNm = rankName
      processed.positionNm = rankName
    }
    else if (duty === '영업소장') {
      processed.dutyNm = '소장'
    }
    else if (duty === '지사장') {
      const rankName = isSupportHeadquarters ? '실장' : '지사장'
      processed.dutyNm = rankName
      processed.positionNm = rankName
    }
    // ... 기타 직책들
  }
  
  return processed
}
```

## 기술적 학습

### 복잡한 비즈니스 로직 처리 전략
1. **단계별 분할**: 문제를 작은 단위로 나누어 해결
2. **우선순위 명확화**: 예외 → LVL → 직책 순서로 처리
3. **테이블 기반 매핑**: 하드코딩 대신 매핑 테이블 활용

### 코드 설계 원칙
- **단일 책임 원칙**: 각 함수는 하나의 매핑만 처리
- **가독성 우선**: 복잡한 로직도 읽기 쉽게 구조화
- **확장 가능성**: 새로운 매핑 규칙 추가 용이
- **디버깅 용이성**: 각 단계별 로그와 검증
