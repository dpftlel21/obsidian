# 테이블 뷰포트 최적화

## 🚨 문제 상황
**아이패드 프로, 아이패드 에어에서 테이블 하단이 뷰포트 아래로 잘려서 보임**

### 발생 환경
- 영향 페이지: 전표, 영업수지, 일일잔액, 면접자현황, 퇴직금 (5개)
- 기기: 태블릿 (아이패드 프로, 아이패드 에어)
- 증상: 테이블 하단이 완전히 아래로 넘어가서 스크롤해야 보이는 상황

### 기존 구조 문제점
```css
/* 기존 코드 — Card 컴포넌트에 직접 dvh 단위 사용 */
mobile:h-[75dvh] tablet:h-[82dvh]
```

## 🔍 원인 분석

### dvh 단위의 한계
1. **브라우저 UI 변동성**: 주소창이 숨겨졌을 때와 보일 때의 높이 차이
2. **기기별 차이**: 브라우저 상단 UI (주소창, 탭바) 높이가 전부 다름  
3. **콘텐츠 변동성**: 필터 영역의 높이도 검색 조건 개수에 따라 달라짐
4. **하드코딩 문제**: `75dvh`, `82dvh` 같은 값은 어떤 기기에서든 정확하지 않음

### 레이아웃 구조
```
┌─────────────────────────────┐ ← window.innerHeight (브라우저 전체)
│  브라우저 주소창/탭바          │
├──────────────────────────────┤
│  앱 사이드바 + 상단 헤더       │
├──────────────────────────────┤
│  필터 영역 (검색 조건)         │
├──────────────────────────────┤ ← rect.top (여기부터 측정)
│                              │
│  ★ 테이블 영역 ★              │ ← available = innerHeight - top - 10
│  (이 높이를 JS로 계산)         │
│                              │
├──────────────────────────────┤ ← 10px 하단 여백
└──────────────────────────────┘
```

## ✅ 해결 방법

### 핵심 아이디어
**CSS로 추정하지 말고, 실제 렌더링된 요소의 위치를 JavaScript로 측정해서 남은 공간을 정확히 계산**

### 구현 코드 (페이지 레벨)

```tsx
// 1. import 추가
import { useRef, useLayoutEffect } from 'react'

// 2. ref 생성
const tableWrapperRef = useRef<HTMLDivElement>(null)

// 3. useLayoutEffect로 높이 계산 (페인트 직전 실행 → 깜빡임 없음)
useLayoutEffect(() => {
  const updateHeight = () => {
    const el = tableWrapperRef.current
    if (!el) return
    const top = el.getBoundingClientRect().top  // 뷰포트 상단에서 요소까지 거리
    const available = window.innerHeight - top - 10  // 남은 가용 공간
    el.style.height = `${Math.max(available, 200)}px`  // 최소 200px 보장
  }

  updateHeight()

  // 리사이즈, 회전 시 재계산
  window.addEventListener('resize', updateHeight)
  window.addEventListener('orientationchange', () => setTimeout(updateHeight, 100))

  return () => window.removeEventListener('resize', updateHeight)
}, [])

// 4. JSX — wrapper div에 ref 연결
<div ref={tableWrapperRef} className="mt-3">
  <SomeTable />  {/* 테이블 컴포넌트 */}
</div>
```

### 테이블 위젯 레벨 변경
```diff
# Card 컴포넌트에서 dvh 고정값 제거, h-full로 부모 높이 상속
- <Card className="mt-3 mobile:h-[75dvh] tablet:h-[82dvh] flex flex-col">
+ <Card className="h-full flex flex-col">
```

## 📐 핵심 공식

### 높이 계산
```javascript
available height = window.innerHeight - element.getBoundingClientRect().top - 10px(여백)
```

### useLayoutEffect vs useEffect
- `useEffect`: 브라우저가 화면을 그린 **후** 실행 → 높이 변경 시 한 프레임 깜빡임 발생
- `useLayoutEffect`: 브라우저가 화면을 그리기 **직전** 실행 → 깜빡임 없이 즉시 반영
- **레이아웃 관련 DOM 조작은 반드시 `useLayoutEffect` 사용**

## 🎯 검증 방법

### 테스트 시나리오
1. **기기별 테스트**: 아이패드 프로, 아이패드 에어, 다양한 태블릿
2. **회전 테스트**: 세로 ↔ 가로 모드 전환 시 높이 재계산 확인
3. **브라우저 UI 변경**: 주소창 숨김/표시 시 동적 조정 확인
4. **필터 변경**: 검색 조건 추가/제거 시 테이블 높이 자동 조정

### 성능 확인
- 리사이즈 이벤트 디바운싱 없이도 부드러운 동작
- `orientationchange` 시 100ms 지연으로 안정화
- 최소 200px 높이 보장으로 극단적 상황 방지
