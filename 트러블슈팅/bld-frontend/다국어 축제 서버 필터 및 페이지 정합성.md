# 다국어 축제 서버 필터 및 페이지 정합성

## 배경
다국어 환경에서 축제/이벤트 목록·상세가 언어에 따라 잘못된 결과를 보이거나 페이지 정합성이 깨졌다. `616624c`(2026-09-11)에서 언어 파라미터와 캐시 키, 페이지 메타를 정비했다.

## 증상
- 언어를 바꿔도 이전 언어의 이벤트 목록/상세가 캐시에서 그대로 노출.
- 필터(키워드·상태) 적용 시 총 개수·총 페이지 수가 실제와 어긋남.

## 원인
1. **언어 미전송·캐시 키 누락**: `searchEvents`/`getEventDetail`가 언어를 명시적으로 보내지 않았고, `eventQueryKeys.detail`이 `lang`을 포함하지 않아 **언어가 달라도 같은 캐시 키**를 써서 이전 언어 결과가 재사용됐다.
2. **페이지 메타 불일치**: 필터 적용 여부와 무관하게 페이지·총계 메타가 고정되어 정합성이 깨졌다.

## 해결
### 1) 언어를 항상 명시 전송 (한국어 기본도 명시)
```ts
// api.ts — searchEvents
params: { ...restParams, lang: params.lang ?? 'ko' }
// getEventDetail(eventId, lang = 'ko') → params: { lang }
```

### 2) 캐시 키에 lang 포함
```ts
// queries.ts
detail: (eventId, lang = 'ko') => [...eventQueryKeys.all, 'detail', eventId, lang] as const,
const normalizedParams = { ...params, lang: params.lang ?? 'ko' };
// search/detail 쿼리를 normalizedParams(lang 포함)로 keying → 언어별 캐시 분리
useEventDetailQuery(eventId, enabled = true, lang = 'ko')
```

### 3) 응답 타입에 언어·fallback 메타 추가
서버가 요청 언어와 다른 언어로 대체했을 때를 표기하도록 타입을 확장.
```ts
// types.ts
interface EventSearchParams { lang?: string; }
interface EventSummary { language?: string; fallbackApplied?: boolean; }
interface LikedEventSearchParams { language?: string; fallbackApplied?: boolean; }
```

## 검증
- `api/events/api.test.ts`: 검색이 한국어 기본을 명시 전송(`{ page:0, size:20, lang:'ko' }`)하고, 상세도 `{ lang }`을 보내는지 검증.
- `FestivalView.test.tsx`: 필터 여부에 따라 `totalCount`/`totalPages`가 달라지고 `fallbackApplied`가 반영되는 페이지 정합성 시나리오 추가.
