# 좋아요 및 여행선 보관 상태 정합성

## 배경
좋아요(찜)와 여행선 보관(스크랩) 상태가 화면 간·요청 간 어긋나던 문제를 `3b3527d`(2026-09-21)에서 캐시 정합성 중심으로 정리했다. 코스 상세 액션도 함께 정돈했다.

## 증상
- 코스 상세에서 좋아요/보관을 눌러도 **마이페이지·브라우즈 목록의 상태가 즉시·일관되게 반영되지 않음**.
- 저장/해제 반복 시 개수(`likeCount`)나 보유 여부가 어긋남.
- 코스 상세의 액션(저장/해제/이동) 동작이 불명확.

## 원인
좋아요와 보관이 **서로 다른 경로로 개별 관리**되고, 대부분 `invalidateQueries`만 호출하는 방식이라(낙관적 업데이트·롤백 없음) 서버 refetch 완료 전까지 화면별 상태가 달랐다. 회원의 관계 상태(멤버십)를 중앙에서 갱신하는 캐시도 없었다.

## 해결
### 1) 좋아요·보관을 하나의 relation 모델로 통합
```ts
const key          = relation === 'like' ? 'likedCourseIds'  : 'scrappedCourseIds';
const collectionKey = relation === 'like' ? 'liked'          : 'scraps';
const dateKey      = relation === 'like' ? 'likedAt'         : 'savedAt';
```
두 동작이 같은 헬퍼·캐시 갱신 경로를 타도록 일원화했다.

### 2) 멤버십 캐시 + 낙관적 업데이트·롤백·서버 정합
```ts
onMutate: async (courseId, context) => {
  await queryClient.cancelQueries({ queryKey: courseQueryKeys.all });
  // 이전 스냅샷 저장 후 membership/컬렉션 캐시를 낙관적으로 갱신
  queryClient.setQueryData<CourseMembership>(courseQueryKeys.membership(accountId), (m) => /* toggle */);
},
onError: (error, variables, mutationContext) => {
  // 실패 시 스냅샷으로 롤백
  mutationContext?.snapshots.forEach(([queryKey, data]) => queryClient.setQueryData(queryKey, data));
},
onSuccess: async (data) => {
  // 서버 응답(data.liked, likeCount)으로 확정 후 무효화
  await queryClient.invalidateQueries({ queryKey: courseQueryKeys.all });
},
```
- `courseQueryKeys.membership(accountId)`에 회원별 관계 상태를 두어, 상세·마이페이지·브라우즈가 **같은 소스**를 읽도록 했다.
- 즉시 반영(낙관적) → 실패 롤백 → 서버 값 정합의 3단계로 화면 간 불일치를 제거.
