### 📝 문제 설명
> [!bug] **What happened?**
> 
> **현상**: 
> - 파일 목록에서 특정 확장자(.DOCX, .XLSX 등 대문자)의 아이콘이 표시되지 않음
> - 일부 파일은 기본 아이콘 대신 깨진 이미지 아이콘으로 표시
> - 동일한 파일 타입이라도 확장자 대소문자에 따라 다르게 표시
> - 아이콘 로드 실패 시 아무것도 표시되지 않아 사용자 혼란 발생
> 
> **발생 시점**: 
> - 파일 목록 페이지 로드 시
> - 파일 업로드 후 목록 갱신 시
> - 특히 사용자가 업로드한 파일의 확장자가 대문자인 경우
> 
> **영향 범위**:
> - EMK Frontend의 모든 파일 목록 컴포넌트
> - 문서 관리, 첨부파일 뷰어 등 파일을 다루는 모든 페이지

## 🔬 근본 원인 분석 (Root Cause Analysis)

### 📊 5 Whys 분석
1. **Why 1**: 왜 이 문제가 발생했나?
   - 답: 파일 확장자 대소문자를 구분하여 아이콘 매핑을 하기 때문

2. **Why 2**: 왜 대소문자를 구분하게 되었나?
   - 답: 파일 확장자 추출 시 toLowerCase() 처리를 하지 않았기 때문

3. **Why 3**: 왜 toLowerCase() 처리를 하지 않았나?
   - 답: 초기 개발 시 모든 파일이 소문자 확장자로 통일되어 있다고 가정했기 때문

4. **Why 4**: 왜 아이콘 로드 실패 시 아무것도 표시되지 않나?
   - 답: 이미지 로드 실패에 대한 에러 핸들링(onError)이 없었기 때문

5. **Why 5**: 왜 에러 핸들링이 없었나?
   - 답: 초기 개발 시 모든 아이콘 파일이 존재한다고 가정하고 예외 상황을 고려하지 않았기 때문

### 🎯 근본 원인
> [!important] **Root Cause**
> 
> **주원인**: 파일 확장자 정규화 미처리 + 이미지 로드 실패에 대한 폴백 처리 부재
> 
> **세부 원인들**:
> 1. 파일 확장자 추출 시 대소문자 정규화 누락
> 2. 아이콘 매핑 테이블이 소문자만 지원
> 3. 이미지 로드 실패 시 onError 핸들러 미구현
> 4. 기본(폴백) 아이콘 경로 미설정
> 5. 존재하지 않는 파일 타입에 대한 처리 로직 부재

## 🔄 재현 단계 (Reproduction Steps)

### 📝 Step-by-Step 재현
1. **전제조건**: 
   - EMK Frontend 애플리케이션 실행
   - 파일 목록 페이지 접근
   - 다양한 확장자의 파일 준비 (대문자 포함)

2. **재현 단계**:
   1. 파일 목록 페이지 접근
   2. 대문자 확장자를 가진 파일 업로드 (예: test.DOCX, report.XLSX)
   3. 파일 목록에서 아이콘 확인
   4. 브라우저 개발자 도구 콘솔에서 404 에러 확인
   5. 존재하지 않는 확장자 파일 업로드 (예: test.xyz)

3. **예상 결과**: 
   - 모든 파일 타입에 대해 적절한 아이콘 표시
   - 알 수 없는 파일 타입은 기본 아이콘 표시

4. **실제 결과**: 
   - 대문자 확장자 파일은 아이콘 미표시 또는 깨진 이미지
   - 알 수 없는 파일 타입도 아이콘 미표시
   - 콘솔에 404 에러 발생

> - 화면: 깨진 이미지 아이콘 또는 빈 공간

## 💡 해결 방안 (Solutions)

### 🚀 임시 해결책 (Workaround)
> [!tip] **Immediate Fix**
> **방법**: 파일 확장자를 수동으로 소문자로 변환하여 업로드
> 
> **단계**:
> 1. 파일 업로드 전 확장자 확인
> 2. 대문자 확장자를 소문자로 변경
> 3. 파일 재업로드
> 
> **제한사항**: 
> - 사용자가 매번 수동으로 처리해야 함
> - 근본적인 문제 해결이 아님
> - 기존 업로드된 파일은 여전히 문제 발생

### 🔧 근본적 해결책 (Long-term Fix)
> [!success] **Permanent Solution**
> **방법**: 파일 확장자 정규화 + 폴백 아이콘 처리 구현
> 
> **구현 계획**:
> - [x] 1단계: 파일 확장자 소문자 변환 로직 추가 🗓️ 2026-01-26
> - [x] 2단계: 이미지 로드 실패 시 onError 핸들러 구현 🗓️ 2026-01-26
> - [x] 3단계: 기본 폴백 아이콘 설정 🗓️ 2026-01-26
> - [x] 검증: 다양한 파일 타입으로 테스트 🗓️ 2026-01-26
> 
> **구체적 구현**:
> ```typescript
> // Before (문제 코드)
> const getFileType = (filename: string): FileType => {
>   const extension = filename.split('.').pop(); // 대소문자 그대로
>   const typeMap = {
>     'pdf': 'pdf',
>     'docx': 'word',
>     // ... 소문자만 지원
>   };
>   return typeMap[extension]; // undefined 가능
> };
> 
> const FileIcon = ({ filename }) => {
>   const fileType = getFileType(filename);
>   const iconSrc = getIconPath(fileType);
>   
>   return <img src={iconSrc} alt="file icon" />; // 에러 핸들링 없음
> };
> 
> // After (해결 코드)
> const getFileType = (filename: string): FileType => {
>   const extension = filename.split('.').pop()?.toLowerCase(); // 소문자 변환
>   
>   const typeMap: Record<string, FileType> = {
>     'pdf': 'pdf',
>     'doc': 'word',
>     'docx': 'word',
>     'xls': 'excel',
>     'xlsx': 'excel',
>     'ppt': 'powerpoint',
>     'pptx': 'powerpoint',
>     'jpg': 'image',
>     'jpeg': 'image',
>     'png': 'image',
>     'gif': 'image',
>     'txt': 'text',
>     'zip': 'archive',
>     'rar': 'archive'
>   };
>   
>   return typeMap[extension || ''] || 'unknown'; // 기본값 처리
> };
> 
> const FileIcon: React.FC<FileIconProps> = ({ filename }) => {
>   const fileType = useMemo(() => getFileType(filename), [filename]);
>   const iconSrc = useMemo(() => getIconPath(fileType), [fileType]);
>   
>   return (
>     <img 
>       src={iconSrc} 
>       alt={`${fileType} icon`}
>       onError={(e) => {
>         // 폴백 아이콘 처리
>         e.currentTarget.src = '/icons/default.svg';
>       }}
>       loading="lazy"
>     />
>   );
> };
> ```
> 
> **필요 리소스**: 
> - 개발 시간: 2시간
> - 테스트 시간: 30분
> - 기본 아이콘 디자인: 30분
