## 🔬 근본 원인 분석 (Root Cause Analysis)

### 📊 5 Whys 분석
1. **Why 1**: 왜 이 문제가 발생했나?
   - 답: 결재선 저장 시 printApp 정보가 누락되어 유효성 검사에서 실패

2. **Why 2**: 왜 printApp 정보가 누락되었나?
   - 답: SignLineRegistration 컴포넌트에서 전달받은 데이터의 printApp 필드가 빈 값이거나 undefined

3. **Why 3**: 왜 printApp 필드가 비어있나?
   - 답: 백엔드에서 결재선 조회 시 일부 데이터의 printApp 필드가 null로 반환됨

4. **Why 4**: 왜 백엔드에서 null이 반환되나?
   - 답: 데이터베이스의 PRINT_APP 컬럼에 실제로 null 값이 저장된 레코드들이 존재

5. **Why 5**: 왜 데이터베이스에 null 값이 저장되었나?
   - 답: 이전 버전에서 결재선 등록 시 PRINT_APP 필드가 NOT NULL 제약조건이 없었고, 기본값도 설정되지 않았음

### 🎯 근본 원인
> [!important] **Root Cause**
> 
> **주요 원인**: 데이터베이스 스키마 설계 시 PRINT_APP 컬럼에 NOT NULL 제약조건과 기본값이 설정되지 않아, 기존 데이터에 null 값이 존재하고, 이를 프론트엔드에서 적절히 처리하지 못함
> 
> **부차적 원인**:
> - 프론트엔드 유효성 검사가 서버 응답 데이터의 null 값을 고려하지 않음
> - 에러 핸들링이 사용자 친화적이지 않음
