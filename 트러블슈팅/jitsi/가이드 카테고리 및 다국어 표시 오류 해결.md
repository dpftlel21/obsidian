# 가이드 카테고리 및 다국어 표시 오류 해결

`82ca371`("오류 수정") 커밋은 메시지가 포괄적이지만 실제로는 서로 다른 세 가지 결함을 함께 바로잡은 작업이다.

## 문제 1 — 언어 감지 순서 오류
`languageDetector.web.ts`의 감지 순서(`order`)에서 `configLanguageDetector`가 배열 **맨 뒤**에 push되어 있었다. 그 결과 설정으로 지정한 언어보다 `localStorage`·`navigator` 값이 먼저 적용돼, 구성된 기본 언어가 의도대로 반영되지 않았다.

### 해결
- `configLanguageDetector.name`을 `safeLangQueryDetector` 다음, `localStorage` **앞**으로 이동. 쿼리 → 설정 언어 → localStorage 순으로 우선순위를 바로잡았다.

## 문제 2 — 사용가이드 카테고리 구조 오류
가이드 다이얼로그가 `host`/`participant`의 2분류(`GuideRole`)로만 나뉘어 있고, 노출 섹션을 매 렌더마다 `filter`로 계산해 순서·구성이 일관되지 않았다. 공통 안내 흐름이 별도 카테고리로 정리되지 않아 사용자가 맥락을 잡기 어려웠다.

### 해결
- `guideData.ts`: `GuideRole` 타입을 제거하고 `GuideAudience`(`common`/`host`/`participant`) 3분류로 재정의. `GUIDE_SECTION_ORDER`로 청중별 섹션 순서를 명시하고, `getGuideSections(audience)` 함수로 순서·필터링을 한 곳에서 결정하도록 캡슐화했다(없는 섹션은 명시적으로 throw).
- `GuideDialog.tsx`: `activeRole` → `activeAudience`(기본값 `common`)로 전환하고, `ROLE_LABELS` 대신 `GUIDE_CATEGORY_META`(뱃지·설명·라벨)를 도입해 공통/주최자/참가자 카테고리를 안내 문구와 함께 표시. 렌더 로직을 `getGuideSections`로 단순화했다.

## 문제 3 — 회의 입장 검증 실패 처리
`KdDashboard.tsx`의 입장 로직이 항상 `meetingApi.joinMeeting` API를 호출해 `meeting_id`를 받도록 돼 있어, 이미 선택된 회의가 있어도 불필요한 검증을 타고 실패 시 처리가 부실했다.

### 해결
- 선택된 회의 id(`selectedMeeting?.id`)를 우선 사용하고, 없을 때만 `getMeetingByRoomName(joinRoomName)`으로 조회하도록 변경.
- 회의를 찾지 못하면 `"회의 정보를 확인할 수 없습니다. 잠시 후 다시 시도해 주세요."` 안내 후 `return`으로 조기 종료해, 잘못된(undefined) 회의 id로 입장하는 상황을 차단했다.
