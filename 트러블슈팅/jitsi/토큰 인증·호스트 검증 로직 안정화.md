# 토큰 인증·호스트 검증 로직 안정화

## 문제
초기 화상회의 진입은 JWT 토큰과 URL 파라미터로 방장(owner)/멤버(member) 권한을 판정했는데, 토큰 파싱과 호스트 검증이 불안정해 권한이 잘못 부여되거나 진입이 실패하는 문제가 반복됐다. 2026-05-19~21 사이 여러 짧은 수정 커밋이 이어졌다.

## 원인
- 토큰 발급/저장 시점과 URL의 오너·멤버 파라미터 처리 경로가 어긋나, 같은 사용자가 상황에 따라 다른 권한으로 인식됐다.
- 호스트 검증 기준이 코드에 하드코딩되어 환경(dev/prod)별로 일관되게 동작하지 않았다.

## 해결
- **호스트 검증 설정화**: `797140e`에서 `config-override.js`·`dev-config.js`·`prod-config.js`에 호스트 검증 설정(약 +264라인)을 추가해 환경별로 검증 기준을 제어했다.
- **JWT 미들웨어 권한 분기 정리**: `6079c2c`·`c4c5b75`에서 `features/base/jwt/middleware.any.ts`의 오너/멤버 분기를 바로잡았다.
- **토큰 저장·복원 정비**: `tokenStorage.ts`와 대시보드 진입(`KdDashboard.tsx`)의 인증 분기(`757a1cb`, `56ddb90`)를 정리해 진입 시 권한이 안정적으로 결정되도록 했다.

## 관련 커밋
- `2026-05-19` `56ddb90` 토큰 인증 로직 수정 / `797140e` 호스트 검증 로직 개선 / `f4d2968` 토큰 수정
- `2026-05-20` `757a1cb` Auth API 로직 분기 / `0d8a0c1`·`4857b7b` 토큰·토큰URL 수정 / `c4c5b75` URL 오너·멤버 권한 / `6079c2c` 방장 권한 수정
- `2026-05-21` `ed2447c`·`b027961` 방장·참가자 권한 문제 수정
