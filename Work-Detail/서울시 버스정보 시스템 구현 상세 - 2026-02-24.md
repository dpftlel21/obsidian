## 🔧 핵심 구현 로직

### 1. 정류장 목록 조회 (get_stations)
```php
// Endpoint: GET /busno_info.php?action=get_stations&routeId={노선ID}&areaTyp=sbis
// 공공데이터: getStaionByRoute 호출
```

**반환 데이터 구조:**
| 필드명 | 설명 | 비고 |
|--------|------|------|
| seq | 정류소 순번 | 1, 2, 3 ... |
| stationNm | 정류소명 | |
| gpsX / gpsY | WGS84 좌표 | 카카오맵 렌더링용 |
| transYn | 회차점 여부 | 'Y'일 경우 상행→하행 전환점 |

### 2. 버스 위치 조회 (get_locations) - 2단계 처리

#### 🤔 왜 2단계로 나누어 처리하는가?
**getBusPosByRtid(노선별 조회) 단독 사용의 한계:**
1. **좌표계 문제**: posX, posY가 TM좌표계(196212, 448218)로 반환 → 카카오맵 사용 불가
2. **데이터 누락**: API 문서와 달리 stOrd(정류소 순번) 필드 누락

**→ 해결: 차량 ID별 개별 조회(getBusPosByVehId)로 WGS84 좌표 + 정확한 정류소 정보 확보**

#### Step 1: 노선 전체 버스 목록 조회
```php
// getBusPosByRtid 호출
// 현재 운행중인 차량 목록 확보
// plainNo → plateNo 정규화
```

#### Step 2: 개별 차량 병렬 상세 조회
```php
// curl_multi 병렬 처리 로직
$mh = curl_multi_init();
$handles = [];

// 1. 버스 대수만큼 개별 API 호출 핸들 생성
foreach ($buses as $i => $bus) {
    $ch = curl_init('.../getBusPosByVehId?serviceKey=' . $apiKey . '&vehId=' . $bus['vehId']);
    curl_multi_add_handle($mh, $ch);
    $handles[$i] = $ch;
}

// 2. 모든 요청 동시 실행
do {
    curl_multi_exec($mh, $running);
    curl_multi_select($mh);
} while ($running > 0);

// 3. 결과 수집 및 기존 배열에 병합
foreach ($handles as $i => $ch) {
    $xml = simplexml_load_string(curl_multi_getcontent($ch));
    $vi = $xml->msgBody->itemList[0];
    
    $buses[$i]['gpsX']       = (string)$vi->gpsX;        // WGS84 경도
    $buses[$i]['gpsY']       = (string)$vi->gpsY;        // WGS84 위도
    $buses[$i]['stId']       = (string)$vi->stId;        // 정류소 ID
    $buses[$i]['stationSeq'] = (string)$vi->stOrd;       // 정류소 순번
}
```

### 3. 프론트엔드 지도 렌더링

#### 3-1. 정류장 폴리라인 그리기
```javascript
let turnIndex = stations.findIndex(st => st.transYn === 'Y');
let hasTurn = (turnIndex !== -1);

// 회차점이 없는 노선 방어 코드
if (!hasTurn) turnIndex = stations.length; 

stations.forEach((st, index) => {
    let pos = new kakao.maps.LatLng(st.gpsY, st.gpsX);
    if (index <= turnIndex) upPath.push(pos);   // 상행 (파랑)
    if (index >= turnIndex) downPath.push(pos); // 하행 (주황)
});

// 지도에 폴리라인 추가
new kakao.maps.Polyline({ 
    path: upPath, 
    strokeColor: '#3b82f6' 
}).setMap(map);

if (hasTurn) {
    new kakao.maps.Polyline({ 
        path: downPath, 
        strokeColor: '#f97316' 
    }).setMap(map);
}
```

#### 3-2. 버스 마커 색상 결정
```javascript
// stId 또는 seq로 현재 정류장 인덱스 찾기
let stIdx = currentStationList.findIndex(s => 
    s.stId == bus.stId || s.seq == bus.stationSeq
);

// 방향에 따른 색상 결정
let busColor = '#3b82f6'; // 기본 상행 (파랑)
if (hasTurn && stIdx > turnIndex) {
    busColor = '#f97316'; // 하행 (주황)
}
```

### 4. 정류장 타임라인 모달 (station_view.php)
- **구조**: iframe 기반 별도 뷰
- **데이터 로딩**: Promise.all로 정류장+버스 위치 병렬 조회
- **렌더링 방식**: 
  1. 상/하행 구분하여 정류장별 빈 컨테이너 생성 (예: `id="up-bus-1"`)
  2. 버스 데이터 순회하며 매칭되는 컨테이너에 appendChild

## 🐛 주요 트러블슈팅

### 문제 1: 버스가 아프리카에 찍힘
- **증상**: 카카오맵에 버스 마커가 아프리카 대륙에 표시
- **원인**: API 응답의 posX, posY가 TM좌표계 (196212, 448218 형태)
- **해결**: getBusPosByVehId의 WGS84 좌표(gpsX, gpsY)만 사용

### 문제 2: 타임라인에 버스가 안 보임 (Count=0)
- **증상**: 정류장별 버스 개수가 0으로 표시
- **원인**: 노선별 조회 시 stOrd 필드가 API 응답에 누락
- **해결**: 차량 개별 조회의 stId 및 stOrd 필드로 정류장 매핑

### 문제 3: 경기 버스 조회 시 forEach 에러
- **증상**: 버스 1대일 때 "forEach is not a function" 에러
- **원인**: XML/JSON 파싱 시 배열([]) vs 객체({}) 차이
- **해결**: 
  ```php
  // PHP: 객체일 경우 배열화
  if (!isset($items[0])) $items = [$items];
  ```
  ```javascript
  // JS: Array.isArray() 방어 로직
  if (!Array.isArray(buses)) buses = [buses];
  ```

### 문제 4: 서울 노선도 하행선 색상 오류
- **증상**: 회차점 없는 노선에서 상/하행 색상 분기 오류
- **원인**: transYn 없을 때 turnIndex = -1로 인한 로직 혼선
- **해결**: transYn 없으면 hasTurn = false 처리하여 단일 색상 적용

## ⚡ 성능 최적화 포인트

1. **curl_multi 병렬 처리**: 버스 N대 조회를 순차가 아닌 동시 실행
2. **Promise.all**: 프론트엔드에서 정류장+버스 데이터 병렬 로딩
3. **좌표계 통일**: TM → WGS84 변환으로 추가 좌표 변환 작업 제거
