# 화상회의 세션 관리 및 재접속 안정화

## 개요
화상회의(meeting) 모듈에서 세션 토큰 발급·검증, 안전한 재접속(reconnect)과 세션 인계(session takeover), 웹소켓 서스펜션(suspension)을 다룬 작업이다. 네트워크 단절이나 중복 접속 상황에서 회의 세션이 꼬이지 않도록 세션 소유권과 클라이언트 세션 식별을 정비했다.

## 주요 변경/구현
- **안전한 재접속 및 세션 인계** (`ec8ed35`): `app/api/meeting/router.py`·`service.py`·`schemas.py`·`models.py`를 대폭 개편(service.py +322 규모). `20260824_add_client_session_id.sql` 마이그레이션으로 클라이언트 세션 ID 컬럼을 추가하고, 재접속 계약(reconnect contract) 문서와 세션 리스(session lease) 테스트(`test_meeting_session_lease.py`)를 함께 도입했다.
- **세션 토큰 관리 로직 수정** (`acabd89`): 세션 소유자(session-owner) 상태 처리를 정리.
- **웹소켓 서스펜션** (`65c7aac`, `e3f0c4f`): `session_events.py`에 서스펜션 로직을 추가하고, 관리자 강퇴(admin kick) 테스트(`test_meeting_admin_kick.py`)·세션 이벤트 테스트를 보강했다.
- **회의참여 중복 방지** (`5cc05ab`): `service.py`(+246 규모)에서 동일 사용자의 중복 참여를 막고 관련 오류를 수정.
- **유저 정보 조회 토큰 수정** (`c484d1d`): 화상회의 사용자 정보 조회 시 토큰 처리를 바로잡음.
