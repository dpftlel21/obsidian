## 🏗️ 주요 구현 내용

### 1. 동적 높이 계산 시스템

#### 핵심 구현 패턴 (페이지 레벨)
```tsx
import { useRef, useLayoutEffect } from 'react'

const SomePage = () => {
  const tableWrapperRef = useRef<HTMLDivElement>(null)

  useLayoutEffect(() => {
    const updateHeight = () => {
      const el = tableWrapperRef.current
      if (!el) return
      
      // 뷰포트 상단에서 요소까지의 거리 측정
      const top = el.getBoundingClientRect().top
      
      // 남은 가용 공간 계산 (10px 여백 확보)
      const available = window.innerHeight - top - 10
      
      // 최소 200px 높이 보장
      el.style.height = `${Math.max(available, 200)}px`
    }

    updateHeight()

    // 리사이즈 및 회전 시 재계산
    window.addEventListener('resize', updateHeight)
    window.addEventListener('orientationchange', () => 
      setTimeout(updateHeight, 100)
    )

    return () => {
      window.removeEventListener('resize', updateHeight)
    }
  }, [])

  return (
    <div className="flex flex-col h-full">
      {/* 필터 영역 */}
      <SomeFilter />
      
      {/* 테이블 영역 - 동적 높이 적용 */}
      <div ref={tableWrapperRef} className="mt-3">
        <SomeTable />
      </div>
    </div>
  )
}
```

**핵심 로직**:
- **실시간 측정**: `getBoundingClientRect().top`으로 현재 위치 파악
- **정확한 계산**: 브라우저 UI 변화에 상관없이 정확한 가용 높이 계산
- **이벤트 대응**: 리사이즈, 회전 시 즉시 재계산
- **성능 최적화**: `useLayoutEffect`로 깜빡임 없는 업데이트

#### 테이블 위젯 레벨 변경
```tsx
// Before: CSS 고정값 사용

</Card>

// After: 부모 높이 상속
```

### 2. Fragment 높이 상속 문제 해결

#### 문제 상황 (BusinessRevenueTable)
```tsx
// 문제 코드: Fragment로 인한 높이 상속 차단
return (
  <>
    {isApproving && <LazySpinner />}    {/* Card와 형제 관계 */}
    <Card className="h-full">...</Card> {/* h-full이 무의미해짐 */}
  </>
)
```

#### 해결 방법
```tsx
// 수정: LazySpinner를 Card 내부로 이동
return (
  <Card className="h-full flex flex-col">
    <CardContent className="p-2 flex-1 flex flex-col min-h-0">
      {isApproving && <LazySpinner />}   {/* Card 내부로 이동 */}
      {/* 테이블 내용 */}
    </CardContent>
  </Card>
)
```

**핵심 원리**:
- Fragment는 DOM 노드가 아니므로 CSS 부모 역할 불가
- 형제 요소들이 높이 분배에 영향을 줌
- Card가 wrapper div의 직접 자식이 되도록 구조 개선

### 4. z-index 계층 시스템 재설계

#### 문제: 고정 컬럼이 그룹 헤더를 덮는 이슈
```
기존 z-index:
- 고정 컬럼: 115 (rowSpan=3으로 모든 레벨 관통)
- 그룹 헤더: 101 (Level 2)
→ 수평 스크롤 시 그룹 헤더가 고정 컬럼에 가려짐
```

#### 해결: DataTable.tsx에서 계층 조정
```diff
// shared/ui/composite/data-table/DataTable.tsx

# Level 1: 비고정 ungrouped 컬럼
- zIndex: enableFixedColumns && ... ? 115 : 101
+ zIndex: enableFixedColumns && ... ? 115 : 99

# Level 2: 비고정 그룹 내 컬럼  
- zIndex: enableFixedColumns && ... ? 114 : 100
+ zIndex: enableFixedColumns && ... ? 114 : 98

# Level 3: 비고정 서브그룹 내 컬럼
- zIndex: enableFixedColumns && ... ? 113 : 99
+ zIndex: enableFixedColumns && ... ? 113 : 97
```

**새로운 z-index 계층**:
```
고정 컬럼 (113-115) > 비고정 최상위 (99) > 그룹 헤더 (98) > 서브그룹 (97)
```

## 🚨 트러블슈팅 상세

### 문제 1: dvh 단위의 부정확성

**문제**:
```css
/* 기존: 하드코딩된 뷰포트 높이 */
.mobile\:h-\[75dvh\] { height: 75dvh; }
.tablet\:h-\[82dvh\] { height: 82dvh; }
```

**원인 분석**:
- 브라우저 UI (주소창, 탭바) 높이가 기기마다 다름
- 필터 영역 높이가 검색 조건에 따라 변동
- `dvh` 단위가 동적 UI 변화를 반영하지 못함

**해결**:
```javascript
// JavaScript로 실시간 측정
const top = el.getBoundingClientRect().top
const available = window.innerHeight - top - 10
el.style.height = `${Math.max(available, 200)}px`
```
